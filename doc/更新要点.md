### 1. 项目代码/结构适应新版`Minecraft`和`Neoforge`接口变化

重中之重了啊。一个大版本必然要变动许多接口。  
不过好处是，新版本的源代码没有混淆，比较好反编译了。

- 第一阶段优先完成基础项目构建环境的适配，先保证项目能在目标版本的开发环境中成功编译出无报错的基础产物（具体动作：按 0.1 矩阵升级 Java toolchain、Gradle wrapper、`net.neoforged.moddev` 插件与 NeoForge/Parchment 版本，并重写四条 `*_version_range`，勿停留在"只改个版本号"）
  - **开发运行环境版本隔离**：26.1.2 分支的 run 配置（client/server/gameTestServer/clientData/serverData）均通过 `gameDirectory` 指向独立目录（`run-26.1.2` 系列），与 1.21.1 分支共用的 `run/`（内含旧版 mods）物理隔离，避免跨版本加载 1.21.1 模组导致启动失败；`.gitignore` 已加 `run-*/`。注意 26.1 起 MDG 将原 `data` 运行拆分为 `clientData`/`serverData`（`data()` 预设已不存在）。

- 第二阶段逐个完成核心接口适配后，每完成一个功能模块的迁移，就停下让我做测试，验证该模块的运行表现一致后再推进下一个模块

- Mixin 专项审查（贯穿两阶段、勿并入"接口适配"一笔带过）：`wing_kirin.mixins.json` 现有 15 个 mixin，一半目标为 DS 内部类、一半为 MC 内部类，是跨版本翻车率最高、排查最痛的部分。须逐 mixin 核对 `@Shadow`/访问器目标字段名（随官方映射改名）、`@Inject` 目标方法签名、Access Transformer 与 `compatibilityLevel`，并逐条验证注入点。

### 2. 确认`数据包`等非代码相关结构变迁

数据包也有一些变化，如一些默认文件夹的命名方式、属性名ID变化......等等诸如此类。需要AI自主查阅新版的Wiki来修正。

- ‌资源与配置文件兼容‌：除了数据包结构变迁之外，还要额外核对模组的语言文件、纹理资源路径、模型文件格式、配置文件的序列化规则，新版本Minecraft和Neoforge很可能对这些非代码的资源格式做了调整，很容易出现文件格式不兼容导致的资源加载失败问题。

- `pack.mcmeta` 的 `pack_format`：主包 `src/main/resources/pack.mcmeta`（现写死 `48`）与 `data/wing_kirin/datapacks/` 下四个内置子数据包各自的 `pack.mcmeta` 都要改为新版数值，忘改即整包资源/数据加载失败（最经典的"能启动但全炸"）。

- 内置子数据包（数据包里的数据包）：`data/wing_kirin/datapacks/` 下的 `low_unlock_condition`、`unlock_acquired_abilities`、`innate_low_upgrade_requirement`、`acquired_low_upgrade_requirement`，各自独立的结构与 `pack.mcmeta` 极易被遗忘，需逐一迁移。

- mcfunction 命令语法：仓库有大量 `.mcfunction`（`uuid-dec_to_hex`、`auto_kill` 等），跨大版本命令语法/命名空间/NBT 路径写法常变，须逐条校验命令脚本，而非只改文件夹结构。

- 数据驱动注册表定义格式：`enchantment/`、`damage_type/`、`painting_variant/`、`data_maps/`（`dragon_beacon_data.json`）、`tags/` 等定义本身的新版 schema 变动很大，属"定义格式变化"而非"资源路径"问题，需按 Wiki 逐类核对。

- 自定义字体与 GUI 精灵图：`font/food_tooltip_icon_font.json`（自定义字形 codepoint）、`textures/gui/sprites/`、`textures/gui/custom/mana_icons/` 等，字体 glyph 映射与 GUI 图集格式跨版本有调整，属客户端静默渲染异常高危区。

- `.nbt` 结构文件：`structure/end_spawn_platforms/*.nbt` 为二进制 NBT，版本间格式/字段可能不兼容，需重导出或校验，不能靠"看一眼"发现。

### 3. 使用新版本代码特性优化表现

新版本自然是会增加一些更便捷的接口以提供更简单的实现，据此可以优化代码复杂度和性能表现，需要AI自主对比并改进。
